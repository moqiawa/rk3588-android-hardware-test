# 摄像头空间基线遮挡检测设计

## 目标

在固定场景摄像头测试中可靠识别大面积区域遮挡。即使遮挡物亮度接近原画面，半幅画面不可辨识也必须报告为严重场景变化，而不是“画面正常”或单纯“偏色”。

## 根因

当前基线只存储全帧 RGB 均值与全局 RKNN 特征。它丢失了像素在画面中的位置：覆盖一半画面的物体仍可能维持相近的全局亮度和特征余弦距离，因此无法稳定命中暗部、过曝或 AI 异常阈值。

## 方案

建立基线和录像检测都从同一个缩放后的帧生成 8×8 空间签名。每格记录亮度均值和纹理强度（拉普拉斯方差），基线保存每格的均值与波动范围。检测时逐格计算亮度或纹理偏离；一帧中至少 30% 区块偏离时标记为“区域异常”。连续至少 3 个采样帧区域异常时，报告“画面区域被遮挡或场景严重变化”。

RGB 色彩比例检测仅处理稳定的全局色偏；区域异常优先于偏色。现有失焦、过暗、过曝、低对比度规则继续保留。若旧基线不含空间签名，则不把它用于区域遮挡判定，显示需要重新建立该摄像头基线，其他规则和 RKNN 流程照常运行。

## 数据与持久化

`AiFrameFeature` 扩展为可选的 64 格空间签名。`FeatureBaseline` 保存空间亮度/纹理中心和波动；存储格式增加版本标记或可选字段。每路摄像头仍使用独立基线键。旧格式可被读取，但其空间字段为缺失状态且不会误判。

## 采样与性能

录像后继续最多分析 120 帧，基线最多分析 240 帧。空间签名只在现有缩放帧上以纯 Kotlin 计算，不增加 NPU 调用次数；8×8×2 个浮点统计对每个摄像头的存储开销很小。

## 验收

- 半幅画面被不透明、亮度接近背景的物体遮挡时，在连续 3 帧后报告区域遮挡/严重场景变化。
- 相同环境、整体亮度变化或轻微白平衡波动不会触发区域遮挡或偏色。
- 单一异常帧不触发区域遮挡。
- 无空间签名的旧基线不会产生错误区域判定，并提示重新建立基线。
- JVM 测试与 Debug APK 构建通过；RK3588 实机用正常、半幅遮挡、偏色和失焦录像验证。
