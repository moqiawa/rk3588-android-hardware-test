# 摄像头场景模型与 ROI 设计

## 目标

让每路摄像头独立选择固定场景或变化场景，并为固定场景设置可持久化的识别区域（ROI）。当前基线、RKNN 特征、空间诊断、录像质量与局部强光规则复用为固定场景模型；变化场景仅保存选择，暂不运行模型。

## 页面布局

页面保持现有整体比例：顶部约五分之一为六个测试入口，底部为摄像头工作区。摄像头工作区从上到下包括：

1. 摄像头切换栏，显示当前摄像头序号；切换后加载该摄像头的配置、ROI 与基线状态。
2. 横向 16:9 预览区。预览内只显示 ROI 轮廓；不叠加运行指标。
3. 预览下方第一行：导入录像建立基线、录制正常基线、录制并检测。
4. 第二行：固定场景、变化场景、设置 ROI。
5. 右侧紧凑面板：分辨率、曝光补偿、对焦的切换控件，以及实际曝光/支持状态、实时帧率、实际输出分辨率、平均亮度、暗部比例和亮部比例。

固定场景为当前可用模型。变化场景为持久化的占位选择，显示“模型尚未配置”，不运行场景模型或基线操作。

## 数据模型与持久化

每个摄像头保存一个 `CameraSceneProfile`：

- `sceneMode`：`FIXED` 或 `VARIABLE`。
- `roi`：归一化矩形，坐标范围为 0 到 1；缺省值为全画面。

固定场景基线保存建立时使用的 ROI。只有基线 ROI 与当前配置 ROI 相同，才能用于检测。修改 ROI 不删除旧基线数据，但使其不匹配并在 UI 中提示“ROI 已更新，需重建基线”。这样能避免将全画面或旧区域的特征、空间签名与新区域混用。

旧配置迁移为 `FIXED + 全画面 ROI`。旧基线缺少 ROI 元数据时同样视为需要重新建立。

## 检测数据流

固定场景下，视频解码出的每一帧按当前归一化 ROI 裁剪后，才进入：

- 清晰度、暗部、亮部与对比度计算；
- RKNN RGB 输入与色彩特征；
- 8×8 空间签名、遮挡与局部强光判断；
- 基线建立与后续相对过曝判断。

ROI 被限制为有效矩形并保留最小尺寸；无效、越界或过小 ROI 不保存。变化场景不加载固定场景基线，不运行 RKNN 或空间/相对过曝诊断；实时预览、参数控制与常规界面状态保持可用。

## ROI 编辑

点击“设置 ROI”进入编辑态，在预览上显示遮罩与可拖动矩形。用户可移动、调整大小、确认、取消，或重置为全画面。只有确认才写入配置；取消和保存失败均保留原 ROI 与基线状态。

保存成功后，固定场景状态立即刷新为“ROI 已更新，需重建基线”。在变化场景下，ROI 控件保留可编辑和持久化，但不会参与当前未配置模型的检测。

## 异常处理与状态

- 当前摄像头不存在有效固定场景基线：跳过模型诊断并给出建立基线提示。
- ROI 与固定场景基线不匹配：跳过模型诊断并提示重建基线。
- 变化场景：显示模型未配置，不启动模型或基线动作。
- 不支持曝光补偿：右侧状态显示不支持，调节控件不可用。
- 实时帧率或实际输出尺寸不可获得：显示不可用，不伪造数值。

## 测试与验收

单元测试覆盖每摄像头配置隔离、归一化 ROI 裁剪、无效 ROI、ROI 改动使基线失效、固定/变化场景策略，以及检测输入仅包含 ROI 内像素。真机验证覆盖全画面默认 ROI、局部 ROI、摄像头切换、分辨率切换、固定场景基线建立和变化场景占位状态。
