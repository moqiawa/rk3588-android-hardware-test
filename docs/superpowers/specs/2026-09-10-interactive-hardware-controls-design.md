# 交互式硬件控制与结果隔离设计

## 目标

修复硬件测试程序的页面结果串联、切页触发采集，以及摄像头/麦克风实时控制失效问题；在不依赖特定 RK3588 板卡参数的前提下，按设备实际能力提供可验证的控制。

## 页面与测试状态

测试结果和实时会话状态分离。只有用户点击单项“重新测试”或“一键测试”才会运行测试并更新保存的 `TestResult`。页面切换、摄像头预览重建与麦克风实时监测均不得创建、覆盖或保存测试结果。

“一键测试”页面展示全部四项结果；摄像头、扬声器、麦克风和网络页面只展示各自的结果与控制。进入摄像头页只打开预览，进入麦克风页只启动可取消的实时电平监测。

## 摄像头

使用独立 Camera2 会话驱动 `TextureView` 预览。每次选择摄像头后读取其 `CameraCharacteristics`，把可用曝光补偿索引范围、变焦范围、对焦模式、预览尺寸和 AE 帧率范围转为 UI 能力模型。

曝光提供最小值、零值、最大值快捷项及覆盖全范围的滑条；滑条和值均为该设备实际补偿索引，显示对应 EV 步长。变焦范围为 1.0 到设备 `SCALER_AVAILABLE_MAX_DIGITAL_ZOOM`，提供 1.0、2.0（若支持）及滑条。对焦项来自 `CONTROL_AF_AVAILABLE_MODES`。分辨率只来自 `SurfaceTexture` 输出尺寸；帧率只来自 `CONTROL_AE_AVAILABLE_TARGET_FPS_RANGES`。所有选择写入同一个重复 `CaptureRequest`，并在界面显示请求值和相机会话实际可应用的状态/错误。

不支持的能力禁用并清楚说明；打开相机或设置重复请求失败时保留上一个有效会话并显示错误，不伪报已经生效。

## 麦克风

麦克风页列出所有系统输入设备，使用前后按钮及设备选项切换。监测器为所选设备创建 `AudioRecord`、设置首选设备并持续计算短窗口峰值与 RMS dBFS。界面同时显示请求设备和 `routedDevice`，使操作者知道实际使用的麦克风。离开页面、切换设备或销毁组合项时必须停止并释放录音。

实时监测不生成证据、不改变最近一次手动麦克风测试结果。显式测试仍采样并保存证据，并会记录所用麦克风。

## 测试与验证

纯 Kotlin 测试覆盖页面结果可见性、显式测试触发策略、曝光/变焦范围策略、相机参数格式化及 PCM 实时电平计算。平台实际控制通过真实设备验收：变焦画面改变、各曝光档位可达、支持的高分辨率与帧率请求可应用、不同麦克风切换后路由和音量变化正确。

构建前运行所有 JVM 单元测试和 `assembleDebug`；最终 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。
