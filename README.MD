# RK3588 Android 硬件测试

面向 RK3588 Android 设备的本地硬件自检应用。应用使用 Jetpack Compose，提供一键汇总和摄像头、音频、网络、接口四类现场核验页面。所有测试结果和录像/录音证据保留在设备的应用专属存储中。

## 当前功能

| 页面 | 当前能力 |
| --- | --- |
| 一键测试 | 汇总摄像头、扬声器、麦克风、网络测试结果；展示 GPIO、USB、音频设备和视频节点概况。 |
| 摄像头测试 | 多摄像头切换、16:9 实时预览、曝光/对焦/分辨率调整、实际曝光支持/FPS/输出分辨率/亮度显示、固定场景基线、ROI 框选和录像质量诊断。 |
| 扬声器测试 | 调整频率、时长、振幅并播放测试音；导入本地音频，显示播放进度和实际输出设备。 |
| 麦克风测试 | 选择输入设备，实时显示峰值/RMS、输入健康状态和实际路由；执行约 3 秒采样并保存 PCM 证据。 |
| 网络测试 | 显示当前网络、IP、DNS、网关、Wi-Fi 链路信息和实时收发速率；使用公共 CDN 下载测试估算速率。 |
| 接口测试 | 每 300 ms 只读刷新 GPIO；枚举 USB 外设用途、音频输入/输出、摄像头/视频节点和网络接口。 |

## 摄像头测试

### 页面与实时参数

摄像头页的上方保留六个测试入口；下方工作区使用左侧预览、右侧参数与状态的布局。

- 左侧为 16:9 实时预览，预览下方第一行依次是“导入录像建立基线”“录制正常基线”“录制并检测”；第二行是“固定场景”“变化场景”“设置 ROI”。
- 右侧显示摄像头切换、曝光补偿、对焦和输出分辨率设置，以及 Camera2 实际回调产生的曝光支持状态、实时帧率、实际输出尺寸、平均亮度、暗部比例和亮部比例。
- 某项指标无法由设备提供时会显示“不可用”，不会用 0 伪造数值。切换摄像头后，实时指标会继续投递到新摄像头的状态区域。
- 录像进行期间会锁定相关操作并暂停实时亮度采样，以兼容仅支持有限输出流组合的相机。

### 固定场景、ROI 与基线

每路摄像头均按摄像头 ID 独立保存场景模式、ROI 和基线。

1. 选择“固定场景”。
2. 可直接使用全画面，或按“设置 ROI”后在预览上拖动框选区域；黄色框为尚未保存的草稿。也可用四条边滑杆微调。
3. 按“确认”保存 ROI，再通过导入正常录像或录制正常基线建立该摄像头的基线。
4. 使用“录制并检测”录制 8 秒视频并完成诊断。

ROI 改动后，旧基线会显示“ROI 已更新，需重建基线”，不会被用于新的区域。旧版本建立的、没有 ROI 元数据的基线同样需要重建。

固定场景下，质量规则、RKNN 特征、空间遮挡、局部强光和相对过曝都只使用 ROI 内像素。基线会保存亮度分组、颜色特征、亮部比例和 8×8 空间亮度/纹理签名。

### 录像诊断结果

一次录像最多分析 120 帧，按最差 10% 帧汇总以下数据：清晰度、暗部比例、亮部比例、对比度、AI 状态、异常分、亮度组、相对过曝基线组/阈值/当前亮部比例，以及局部强光区域比例。

- 清晰度偏低时提示“可能失焦或画面模糊”。
- 暗部比例高时提示“画面过暗或镜头被遮挡”。
- 基线相对亮部明显升高、或满足局部连续高亮区域条件时提示“画面过曝（局部强光）”。
- 8×8 空间签名连续显著变化时提示“画面区域被遮挡或场景严重变化”。
- RKNN 不可用、缺少基线或 ROI 不匹配时，会明确显示原因，不会把未分析结果当作正常。

这些阈值用于硬件自检初筛；应使用目标设备上的正常、遮挡、失焦、局部强光等样本持续校准。

### 变化场景

“变化场景”目前仅是每路摄像头持久化的占位选择，状态显示为“变化场景模型尚未配置”。此模式不允许导入/录制基线或录制检测；仍可预览、切换摄像头、调整曝光/对焦/分辨率及设置 ROI。当前固定场景模型不会在变化场景下运行。

## 环境要求

- Android Studio（可使用内置 Gradle）
- JDK 17
- Android SDK：编译 SDK 36；最低 Android 8.0（API 26）
- ABI：`arm64-v8a`
- 目标设备：RK3588 Android 设备；摄像头、麦克风、扬声器、Wi-Fi、USB 与 GPIO 由实际硬件和系统提供。

摄像头 AI 功能包含本地 RKNN 模型 `camera_quality_feature.rknn`、原生特征提取库和 RKNN 运行时。运行时加载失败时，应用会保留规则诊断并显示 AI 不可用原因。

## 构建、安装与测试

在项目根目录执行：

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug
.\gradlew.bat installDebug
```

调试 APK：`app/build/outputs/apk/debug/app-debug.apk`。

本地 JVM 单元测试覆盖音频电平/播放策略、录像质量规则、基线与 ROI 纯逻辑、场景操作状态、Camera2 指标回调状态、网络速率、GPIO、USB 和结果模型。真实相机、音频、网络与接口功能仍须在目标设备上验证。

## 权限、证据与限制

- 首次运行请允许摄像头和录音权限；清单同时声明互联网、网络状态和 Wi-Fi 状态权限。
- 摄像头录像和麦克风 PCM 证据写入应用专属外部存储的 `evidence/` 目录，不会写入本项目。
- GPIO 固定读取 `/sys/class/gpio_sw/io1` 至 `io4`，节点不存在时显示不可用；应用只读，不改变电平。
- USB 页展示内核已识别的设备用途；普通 Android 应用无法确定是否被其他应用独占。
- Wi-Fi 名称和链路速率受 Android 版本、位置/系统权限和厂商实现限制，缺失时会显示不可读取或未提供。
- 公共 CDN 测速受网络环境、服务端和调度影响，只是当前链路的估算值。
- 当前开发环境未配置 ADB；真机验收请重点验证摄像头切换后的实时指标、分辨率切换、ROI 变更后重建基线、局部手电筒、半画面遮挡、失焦与偏色。

## 本地诊断文件

构建日志统一放在 `logs/build/`，每个测试场景保留成对的 `.stdout.log` 与 `.stderr.log` 文件。JVM 堆转储放在 `diagnostics/heapdumps/`，通常体积较大且可能包含运行时敏感数据，不应提交或对外共享。
